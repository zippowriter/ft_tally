# 型推論のテストリスト

[課題文](../../ft_tally.md) の IV.2 に基づく。上から順にテストを1件ずつ書く。今回の作業はユーザーの指示に従い、各ステップの承認を省略する。完了した項目にはチェックを入れる。

課題文で公開 API の名前や形式は指定されていない。テストでは、`inferValue(text)` がセルを変換し、`inferTypes(rows)` が `parseCsv` の `rows` を受け取って変換済みの行を返し、`isNumericColumn(values)` が変換済みの1列を判定する構成を想定する。

1. [x] `42` と `7` を整数の `42` と `7` に変換する。
2. [x] `-3.5` を負の小数 `-3.5` に変換する。
3. [x] `1e3` を数値の `1000` に変換する。
4. [x] 空文字列を `null` に変換する。
5. [x] スペース、タブ、改行だけで構成された文字列を `null` に変換する。
6. [x] `NaN` と `Infinity` を元の文字列のまま返す。
7. [x] `0x1F` を元の文字列のまま返す。
8. [x] `12abc` を元の文字列のまま返す。
9. [x] `true` と `false` を対応する真偽値に変換する。
10. [ ] `  Tokyo  ` のような通常の文字列は前後の空白も含めて保持する。
11. [ ] `parseCsv` の複数行・複数列を変換し、行順と列名を保ったまま各セルに変換規則を適用する。数値と文字列が混在する列でもセルごとに変換する。
12. [ ] 数値だけの列を数値列と判定する。
13. [ ] 数値と `null` だけの列を数値列と判定する。
14. [ ] 数値と文字列が混在する列を数値列と判定しない。
15. [ ] 数値と真偽値が混在する列を数値列と判定しない。

## 期待結果が未確定のケース

- 全値が `null` の列と、ヘッダーだけの CSV のように値が0件の列を数値列とみなすか。数値が1件以上必要かは課題文に明記されていない。
- ` 42 ` や ` true ` のように、変換候補の前後に空白がある入力を変換するか。
- `+42`、`.5`、`1.` など、例示のない十進数表記を受理する範囲と、`1e309` のように変換すると非有限値になる入力の扱い。
